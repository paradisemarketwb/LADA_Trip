# LADA Trip v0.2 Engineering — единый план испытания R2

Дата: 2026-11-15. Модель: Humax AIVI-N3111RV, Android 9 (API 28). Используемая на машине сборка: SOP12-R2.231031.001. Исследованные ранее OEM-бинарники из OTA — R1, поэтому соответствие поведенческих интерфейсов на R2 ещё не установлено.

## Сборка и установка

1. Откройте `android/` в Android Studio с JDK 17, Gradle 8.7 и Android SDK 35. Соберите `assembleDebug`; либо загрузите проект в приватный GitHub и скачайте `LADA-Trip-v0.2-engineering-debug-apk` из GitHub Actions.
2. APK устанавливается поверх v0.1 с тем же `applicationId=ru.ladatrip.app`, **если подпись совпадает**. При смене подписи Android может потребовать удаление старого APK, что удалит локальные поездки и настройки. Не удаляйте v0.1 без резервной копии CSV/GPX и серверного ключа.
3. Не активируйте инженерный режим в движении. Проверяйте систему на стоящем автомобиле. Для фиксации изменений скорости безопаснее использовать пассажира, запись лога или тест после остановки.

## Уровень 1 — Android Automotive

1. `LADA Trip` → `LADA Vehicle Probe` → `Запросить доступные разрешения автомобиля`.
2. Запишите, объявлены ли в установленной R2 `CAR_SPEED`, `CAR_ENERGY`, `CAR_POWERTRAIN`; для `CAR_MILEAGE` и `CAR_VENDOR_EXTENSION` не ожидайте выдачи системных прав обычному APK.
3. Нажмите `Проверить свойства CarPropertyManager`. Дождитесь результата или тайм-аута 8 секунд.
4. Проверьте `PERF_VEHICLE_SPEED`, `ENGINE_RPM`, `IGNITION_STATE`, `CURRENT_GEAR`, `GEAR_SELECTION`, `FUEL_LEVEL`, `PARKING_BRAKE_ON`, `FUEL_LEVEL_LOW`.
5. Если значение появилось — сравните показания с приборной панелью. **Не используйте данные в функциях безопасности до верификации.** Для уровня топлива сырой формат/единицы требуют отдельной проверки.
6. Оставьте экран открытым, убедитесь, что обновление доступных свойств приходит через callback. Если подписка не поддерживается, приложение честно покажет «Доступно (без подписки)».

## Уровень 2 — Yandex CAN

Нажмите `Проверить CanService`. Возможные исходы: сервис отсутствует, не экспортирован, требуется закрытое разрешение, `bindService=false`, SecurityException, подключён Binder с descriptor. Последнее **не означает**, что удалось прочитать CAN-параметры, и не даёт повода выполнять случайные AIDL вызовы.

## Уровень 3 — необязательный Accessibility

1. Включить вручную через кнопку настроек доступности Android, только после ознакомления с описанием службы.
2. Открыть именно инженерный экран CAN из приложения, если Activity экспортировано. Если Android блокирует запуск, зафиксировать это и не обходить защиту.
3. Вернуться в LADA Trip и нажать `Показать считанные значения меню`. Данные должны относиться **только** к `com.humaxdigital.avtovaz.engineeringmode`, без личных сведений из других приложений.
4. Отключить службу доступности после испытаний, если она больше не нужна.

## Экспорт

Нажать `Сохранить инженерный отчёт JSON на USB`. Выбрать USB-накопитель через системное окно Android. Файл `lada-trip-engineering.json` содержит состояния, ошибки, значения, доступность API и разрешений. Не содержит историю GPS, координаты, ключ устройства или токен Telegram. Сообщение `Нет свежих данных` для Accessibility — нормальный результат, если OEM-экран не отдаёт текст.

## Приёмочные условия

- LADA Trip по-прежнему записывает GPS и отправляет координаты при появлении интернета, без зависимости от успешного CarPropertyManager/CanService.
- Нет root, системных модификаций, CAN-записи, неизвестных Binder transact, скрытых автоматических кликов.
- Приложение не падает при отсутствии `android.car`, отказе в разрешении, неэкспортированном сервисе и недоступной Activity.
- Инженерный JSON экспортируется и открывается на ПК. Не путать «компонент есть» с «параметр автомобиля реально доступен».
