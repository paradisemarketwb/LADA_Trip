# LADA Trip — v0.2 Engineering (Android 9, LADA EnjoY Vision Pro)

Самостоятельный проект записи GPS-поездок и надёжной отправки координат владельцу через защищённый шлюз Telegram. **Не связан с CarPlay.**

## Состав
- `android/`: Android Java, minSdk 28, экран 960×1280, без Google Play Services и root.
- `server/`: Node.js 20+ HTTPS-terminating reverse proxy backend, выдача Telegram уведомлений, дедупликация и аудит.
- `.github/workflows/android.yml`: GitHub Actions собирает debug APK, выдаёт artifact.
- `docs/TEST_PLAN.md`: проверка на магнитоле и экспорт диагностики на USB.

## Первая версия
- Foreground GPS monitoring, автостарт после `BOOT_COMPLETED` (при разрешениях и если прошивка не блокирует).
- SQLite офлайн-поездки, точки, остановки, пробег, длительность, последняя позиция.
- Реакция на появление интернета: очередь JSON-событий, три попытки с проверкой HTTP-ACK, отложенная отправка.
- Уведомления о старте/конце в Telegram **после доставки**; локальное уведомление во время мониторинга.
- Журнал событий, экран настроек, CSV/GPX журнал, JSON диагностика через системный SAF (USB выбирает пользователь).
- API ключ устройства зашифрован AES-GCM Android Keystore; токен Telegram только в backend.

## Предварительные ограничения
- APK здесь не собран: локально отсутствуют Android SDK/Gradle и сеть для их загрузки. Сборку проверяет GitHub Actions после загрузки репозитория.
- В OEM Android 9 GPS, BOOT_COMPLETED, foreground service и wake-up должны проверяться на реальной магнитоле.
- События с одинаковым event_id дедуплицируются сервером. Не обещается строгая exactly-once доставка при аварийном отключении сервера между отправкой Telegram и записью ACK.
- Карты офлайн на экране пока нет: маршруты сохраняются и экспортируются GPX; ссылка на карту есть в Telegram.

## Сборка Android
Открыть папку `android/` в Android Studio (JDK 17, Android SDK 35); Run/Build APK, либо `gradle assembleDebug` (Gradle 8.7+). Debug APK: `android/app/build/outputs/apk/debug/app-debug.apk`.

## Сервер
В `server/`: Node 20+, создать `.env` из `.env.example` и экспортировать переменные в окружение, затем `node index.js`. Локально сервер слушает **только** 127.0.0.1, внешний доступ должен идти через TLS reverse proxy (Nginx/Caddy/etc). `node --test` запускает тесты API и дедупликации.

На магнитоле указать `https://ваш-домен`, device ID (`lada-vesta-01`) и выданный сервером случайный 32-байтовый токен. Сам Telegram-токен и chat ID остаются на сервере.

## Публикация в публичный GitHub — только владелец вносит изменения

На Windows откройте `CREATE-PUBLIC-GITHUB.cmd` из этой папки. Он проверит `gh`, выполнит вход через браузер под аккаунтом владельца, создаст публичный `paradisemarketwb/LADA_Trip`, отправит исходники и попробует включить защиту `main`. Подробности — `PUBLIC-REPO-START.md`.

**Ни одного стороннего пользователя не добавляем в collaborators.** Публичность позволяет читать и форкать код; она не означает право менять оригинальный репозиторий.

## Инженерный режим v0.2.0 (read-only)

На главном экране кнопка **LADA Vehicle Probe** открывает отдельный экран. GPS, история поездок и Telegram-сервер остались без изменений.

- **Уровень 1 / CarPropertyManager:** через рефлексию к установленной `android.car` (без стороннего `android.car.jar` в APK) пробует подключиться к CarService, запрашивает только опасные (dangerous) разрешения по кнопке, проверяет восемь стандартных автомобильных свойств и подписывается на обновления, если автомобиль поддерживает callback. Состояния различаются: не выдано разрешение, нет конфигурации/доступа, ошибка чтения, нет значения, успешно. Доступность зависит от прошивки Humax R2.
- **Уровень 2 / CanService:** проверяет `exported` и требуемое разрешение `ru.yandex.yap.hal.services.CanService`, пробует `bindService` и читает только Binder interface descriptor. **Никаких непроверенных AIDL-транзакций** (в R1 видимые методы `CanManagerImpl` имеют пустую реализацию). Разрывает привязку через 3 секунды.
- **Уровень 3 / Accessibility:** необязательная служба, которую владелец включает вручную в системных настройках Android. Читает только текст окна `com.humaxdigital.avtovaz.engineeringmode`, когда пользователь лично открыл инженерное меню. Никаких скриншотов, кликов или чтения других приложений. Данные живут только в оперативной памяти (до 10 минут), если пользователь не экспортировал отчёт.
- **Отчёт:** JSON через SAF/USB; не содержит ключей Telegram, координат, маршрутов или пользовательских данных.

Ограничения: тестируется **установленная R2**, а не предположения по статической OTA R1; обычный APK не получает права `signature|privileged`. Может потребоваться Android SDK/платформенный runtime, которые отсутствуют на обычном телефоне. Наличие автомобиля с динамическими парковочными линиями не доказывает доступ к углу руля из приложения.

**Сборка:** инструкция выше. На этой стадии выполнена проверка синтаксиса Java, XML и серверных тестов, **не выполнены Gradle-сборка APK и проверка в автомобиле** (Android SDK в текущем окружении отсутствует).

**Проверка за один визит к машине:** `docs/ENGINEERING_TEST_PLAN.md`. Соберите инженерный APK, откройте LADA Vehicle Probe, проверьте разрешения → CarPropertyManager → CanService → (необязательно) Accessibility, экспортируйте `lada-trip-engineering.json` на USB. В разделе о работе двигателя разделяйте стоянку, холостой ход, движение и задний ход — только если безопасно и не отвлекаясь за рулём.
